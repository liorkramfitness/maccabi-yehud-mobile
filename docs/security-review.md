# בדיקת יציבות ואבטחה

## מה אומת ומה לא

נבדקו כל קובצי המאגר והכלים הזמינים. אין חיבור Supabase זמין בכלים, אין משתני סביבה עם פרטי Supabase, ואין במאגר כתובת פרויקט, מפתח חיבור, סכמת SQL או מדיניות RLS. הגדרות החיבור של האפליקציה נשמרות ב-localStorage בדפדפן של המשתמש, ואינן חלק מהמאגר.

אומת בקוד שכל חמש הקריאות כוללות סינון `owner_id`, וששמירות כוללות את מזהה המשתמש. **זה אינו מוכיח ש-RLS מופעל או שההרשאות תקינות.** משתמש יכול לעקוף סינון שמבוצע בדפדפן. לא בוצעו קריאות או כתיבות למסד האמיתי, ולא שונו הרשאות.

## בדיקה נדרשת ב-Supabase

יש לבדוק עבור `my_teams`, `my_players`, `my_team_players`, `my_sessions`, `my_attendance`:

- RLS מופעל, ואין מדיניות נוספת שמאפשרת גישה רחבה יותר בטעות.
- קריאה ועדכון מותרים רק לבעל הרשומה; INSERT ו-UPDATE אוכפים `owner_id = auth.uid()` באמצעות WITH CHECK.
- משתמש לא מחובר אינו יכול לקרוא או לשנות מידע אישי.
- שיוכים ונוכחות אינם יכולים להפנות לקבוצה, שחקן או אימון של בעלים אחר.
- קיים אילוץ ייחודיות על `(session_id, player_id)` כנדרש ל-upsert.
- קיימים אילוצי טווח ותקינות במסד; אימות בצד הדפדפן בלבד אינו גבול אבטחה.

שאילתות מטא-דאטה לקריאה בלבד, שלא הורצו במסגרת העבודה:

```sql
SELECT n.nspname AS schema_name, c.relname AS table_name,
       c.relrowsecurity AS rls_enabled, c.relforcerowsecurity AS rls_forced
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public'
  AND c.relname IN ('my_teams', 'my_players', 'my_team_players', 'my_sessions', 'my_attendance')
  AND c.relkind IN ('r', 'p');

SELECT schemaname, tablename, policyname, permissive, roles, cmd, qual, with_check
FROM pg_policies
WHERE schemaname = 'public'
  AND tablename IN ('my_teams', 'my_players', 'my_team_players', 'my_sessions', 'my_attendance');
```

קריאת המדיניות היא שלב ראשון בלבד. יש להשלים בדיקות בידוד עם שני משתמשי בדיקה בפרויקט בדיקות נפרד, כולל בקשות ישירות שאינן מסוננות בידי ממשק האפליקציה. אין לבצע בדיקות כתיבה על הנתונים הקיימים ללא אישור.

## התנהגות התיקונים

- התנתקות מנקה מיד נתונים, בחירות, טיוטות וסיסמאות מהאפליקציה. תגובות ישנות מהענן אינן יכולות להחזירם. ההתנתקות היא מקומית למכשיר ואינה מוחקת רשומות בענן. הגדרות החיבור הציבוריות נשמרות.
- פעולת שמירה ננעלת עד לסיום הבקשה ומשתחררת גם בכישלון. אין בכך מניעת כפילויות בין מכשירים או לאחר רענון; לשם כך נדרשים גם אילוצים במסד.
- דקות הן מספר שלם בטווח 0–300; RPE בטווח 0–10 בחצאי נקודות; שנתון חובה, שלם בטווח 2000–2100, בהתאם לטווח הקיים בממשק. שדות דקות ו-RPE ריקים נשמרים כ-null.
- עומס מחושב עבור היום וששת הימים הקודמים לפי `Asia/Jerusalem`, גם אם המכשיר נמצא באזור זמן אחר. נכללים רק אימונים שבוצעו בקבוצה שנבחרה, עם נוכחות הגיע/איחר/חלקי, דקות חיוביות ו-RPE תקין. אפס RPE הוא ערך תקין. הנתונים המקוריים אינם משתנים.
- יצירת שחקן ושיוכו עדיין אינן אטומיות. כישלון שיוך מוצג במפורש; פתרון מלא דורש שינוי בצד המסד ולא נכלל בעבודה זו.

## בדיקות

```sh
npm ci
npx playwright install chromium
npm test
```

לשימוש ב-Chromium מותקן מראש: `CHROMIUM_PATH=/usr/bin/chromium npm test`.

הבדיקות רצות בדפדפן עם Supabase מדומה וחוסמות בקשות רשת אמיתיות. הן בודקות התנתקות, תגובות מאוחרות, לחיצות כפולות, כישלונות, קלט מספרי, תאריכים בישראל, סינון עומסים ותצוגת RTL ברוחבי מובייל. הן אינן מאמתות את RLS, שרת Supabase או Safari באייפון אמיתי.
